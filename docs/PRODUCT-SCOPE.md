# Personal AI OS 产品定义与升级路线

> 当前版本基准：2026-11-12 · 产品名称：Personal AI OS

## 1. 项目定义

**Personal AI OS 是一个用户自托管的个人 AI 工作台。**用户在自己的电脑或服务器上运行它，配置自己的模型服务、数据和执行资源。

它不是：

- 由项目维护者运营的公共 AI 网站或 SaaS；
- 免费云电脑、公共代码执行服务或云存储；
- QQ/OneBot/NapCat 机器人网关；
- 开箱即用的开放注册多租户平台。

产品承诺是：**软件提供工作台和受控执行能力，计算、模型、存储由部署者/用户自行提供。**

## 2. 产品范围

### 当前核心功能

- 邮箱/密码登录与首次管理员初始化；
- 流式对话、会话历史、文件和图片输入；
- OpenAI 兼容模型 Provider；
- 工具调用、风险审批、执行记录；
- 管理员本机沙箱；
- 普通用户可使用自备公网 SSH 服务器或已配对的本机 Agent 执行 Shell/Python；
- 账号级会话、执行记录、Provider 与个人设置隔离；
- 浏览器语音输入、系统语音及可选第三方 TTS。

### 管理员职责

管理员管理**实例级**能力：邮件发送、注册策略、登录防护、系统设置、全局运维及管理员自己的本机执行。

管理员不提供模型额度、用户服务器、云存储或托管运维服务。

### 普通用户职责

普通用户使用自己的账号、模型 Provider/API Key、个人偏好和远程执行服务器。没有配置远程执行器时，可以聊天，但不能让命令落到 AIOS 主机执行。

### 移除的旧整合

OneBot 11、NapCat、QQ 收发与 Termux NapCat 部署不属于 Personal AI OS 核心产品，已从运行接线、工具路由和当前安装脚本中移除。Git 历史中的旧提交仍可能包含早期代码；当前发布树不再启动或打包这些服务。

## 3. 当前多用户隔离完成度

### 已完成

- 首个管理员仅能从 loopback 初始化；空库之外无法再次 bootstrap；
- 管理员和普通用户分别使用实例设置与个人设置文件；模型 Provider/API Key 不共享；
- 普通用户会话 JSON 以 `owner_user_id` 标记，历史会话归首个管理员；
- 会话读取、写入、删除和消息修改按归属过滤；越权返回 404；
- Run 列表、详情、事件和导出按会话归属过滤；
- 普通用户的工具授权记录按本人会话访问；管理员保留全局运维能力；
- 普通用户 Shell/Python 只路由到其自备 SSH 服务器，目标地址校验拒绝 loopback、私网和 metadata。

### 尚未完成（开放注册前必须完成）

- 部署端媒体按账号归属/策略保存；远程存储迁移已实现；文件型工具和上传内容的完整远端命名空间隔离仍需逐项验收；
- 文件 API、持久工作区和导出按用户命名空间隔离；
- 所有工具逐项划定 user/admin 权限，补齐跨账号访问测试；
- 用户数据导出与删除流程、配额及保留策略；
- 公共注册默认关闭；完成上述隔离前不得面向不可信用户开放。

## 4. 执行安全边界

普通用户执行有两种方式：SSH 连接用户自备服务器，或在本人设备运行 AIOS Agent 并主动配对连接。SSH 使用公钥和主机指纹验证；Device Agent 使用一次性配对码和设备令牌。runner 使用 Docker 容器，当前限制包含：

- 非 root 用户；
- 根文件系统只读；`/workspace` 与 `/tmp` 为有容量限制的临时文件系统；
- 容器网络关闭；
- CPU、内存、进程数量、执行时间和输出大小受限；
- 任务结束后容器自动删除。

AIOS 不持有用户服务器密码；用户维护服务器、Docker、SSH 安全组和费用。

## 5. 升级路线

### P0：补齐数据隔离，开放多用户之前

- 媒体元数据和下载端点加入 owner 校验；
- 上传、文件、工作区、导出资源分账号目录或对象命名空间；
- 逐工具定义用户权限矩阵，默认拒绝未明确授权的工具；
- 增加 member A/B 互相读取、修改、删除资源的集成测试；
- 提供管理员停用账号、用户导出/清空个人数据能力。

### P1：BYOS（用户自备存储）

- 定义存储后端接口；
- 对象存储支持直传/签名下载；
- 本地仅保存元数据和可清理缓存；
- 存储凭据按账号隔离并加密。

### P2：完善远程执行

- 多任务并发上限、排队、取消与每账号配额；
- 安全的任务文件上传和结果文件回传；
- runner 版本协商、健康检查和密钥轮换；
- CI 自动构建镜像并执行 Docker 隔离冒烟测试。

### P3：自托管产品体验

- 首次安装向导和环境诊断；
- 备份/恢复与版本迁移；
- 管理员用户列表、邀请、停用、用量统计；
- 独立的服务部署/反代指南；不提供默认公网开放配置。

## 6. 当前发布定位

当前版本适合**个人自托管和受控的小范围测试**，尚不适合宣称为公共多租户 SaaS。媒体、文件隔离和工具权限矩阵完成之前，应保持注册邀请制，并且只邀请可信用户。

本仓库不提供 OneBot/QQ/NapCat 服务，也不承诺免费计算、模型额度或存储空间。

## 用户数据存储 / User data storage

普通用户默认把聊天记录和媒体保存在 AIOS 实例为该账号准备的本地目录；没有远程服务器时，聊天不会因为缺少远程配置而失效。用户配置并测试自己的 SSH 服务器后，可以在“我的账号 → 执行服务器”选择是否迁移已有聊天和媒体。迁移会先复制并回读校验，失败不会删除本地源数据；选择继续本地时也不会自动迁移。远程模式下的新媒体和聊天备份写入该用户专属远程目录，部署端只保留账号/索引和运行所需元数据。

Regular users keep chat history and media in their account directory on the AIOS deployment by default; remote execution is optional and is not required for chat. After configuring and testing their own SSH server, users can choose whether to migrate existing chat/media data. Migration verifies the remote copy before switching and never deletes the local source on failure. In remote mode, new media and chat backups are written to the user's dedicated remote directory; the AIOS deployment keeps only account/index/runtime metadata.


## 7. 用户存储策略

普通用户默认使用 AIOS 部署端的账号目录保存聊天记录和媒体，因此没有远程服务器时仍能正常使用。配置并测试自己的 SSH 执行服务器后，用户可以选择继续本地存储，或迁移到自己的服务器；迁移过程复制后回读校验，失败不删除本地源数据。

远程模式下新媒体和聊天备份写入用户服务器的 `~/aios-data/media/` 与 `~/aios-data/conversations/`。部署端只保留账号、索引和运行所需元数据。上传文件接口只在内存中解析文本，不保存原始文件。

## 8. 真实验收边界

- 本地默认存储、账号隔离、迁移策略和远程读写单元边界已通过自动化测试；
- runner Docker 镜像已在隔离 Ubuntu 24.04 WSL2 环境构建并验证：工作区可写、根目录只读、无网络、超时可终止；
- 真实两台设备之间的 SSH 上传/下载、历史迁移和断线恢复仍需部署者在自己的服务器上做一次端到端验收；
- 公开多用户上线前仍需完成媒体/文件全覆盖集成测试和并发队列/配额策略。


## 本机设备执行器完成度

已实现第一阶段：配对码、设备 token、心跳/长轮询、任务队列、设备撤销、用户/设备归属检查、输出上限和超时状态，以及 Windows/macOS/Linux 可运行的 Python Agent。尚未实现原生 Android/iOS/鸿蒙 App；Android 前台 Agent 可实验，后台和休眠恢复需真实设备继续验收。


## 本机设备执行器支持范围

Windows/macOS/Linux Python Agent 可主动轮询任务，配对后按账号绑定设备；假 Agent 端到端测试通过。Android 仅前台手动运行原型；iOS/鸿蒙没有客户端，后台常驻、系统权限沙箱、应用签名/自动升级和睡眠唤醒仍未完成。真实多设备网络切换/休眠恢复尚需实机验收。任意 Shell 在个人设备上具有该系统账号权限，默认逐任务确认；只配对本人账号的可信设备。
